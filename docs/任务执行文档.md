## 2. 已完成的修复（必须保留，回归时重点验证）

### F1 — DI 字段注入对不可寻址值 panic

- **文件**：`kernel/v3/di/container.go`（`injectFields`）
- **现象**：`integrations/outbox/v3` 的 `TestForRoot_InitRequiresExplicitRegistry` 直接 panic：
  - `reflect: reflect.Value.Set using unaddressable value`
  - `reflect: call of reflect.Value.Set on zero Value`
- **根因**：`ProviderTypeValue` 注册的实例可能是**非指针 struct**，`reflect.ValueOf(instance)` 得到的 `Elem()` 不可寻址；旧代码未校验 `CanSet()`，且未校验依赖值类型是否可赋值，`reflect.ValueOf(nil)` 会产生零 Value。
- **修复**：
  - 指针为 nil 时直接跳过；
  - 仅当 `fv.CanSet()` 才注入；
  - 依赖为 nil / 类型不 Assignable 时跳过。
- **回归测试**：`kernel/v3/di/container_typed_test.go::TestGet_ValueProviderWithStructValueDoesNotPanic`

### F2 — HTTP `Body[T]` / `Form[T]` 未执行 validator 校验

- **文件**：
  - `protocol/http/v3/binding/resolver_bind.go`
  - `protocol/http/v3/binding/resolver_request.go`
- **现象**：`http.New().WithValidatorV10()` 下，`POST /users {"email":"bad"}` 仍然返回 201，校验完全失效；只有 `Bind[Body[T]]` 写法才会校验。
- **根因**：校验只在 `resolveAutoStruct` 与 `buildBoundValue`（`Bind[T]`）里执行；`resolveBody` / `resolveForm` 直接 `decodeTo` 后返回，**没有走 validator**。而官方示例（`cmd/http-demo`）正是 `Body[T]` + `CompositeStruct` 写法。
- **修复**：新增 `validateBoundValue(ctx, obj)` 统一校验入口（只对 struct / *struct 生效，标量 wrapper 如 `Query[int]` 自动跳过），并在 `resolveAutoStruct`、`resolveBody`、`resolveForm`、`buildBoundValue` 四处复用。
- **回归测试**：
  - `protocol/http/v3/http_test.go::TestAdapter_ValidatorV10_BodyWrapper`
  - `protocol/http/v3/http_test.go::TestAdapter_ValidatorV10_CompositeBodyWrapper`
- **E2E 证据**：`POST /users {"email":"bad"}` → `400 {"kind":"Validation","error":"validation failed on Email (email)"}`

### F3 — `Application.Run/Listen` 立即返回，服务进程随之退出

- **文件**：`application/v3/application.go`、`application/v3/runtime.go`
- **现象**：`cmd/http-app-demo` 启动后立刻进程退出（端口未监听），`cmd/ws-app-demo` 同样；调用方不得不自己 `select {}`。
- **根因**：`startAdapters()` 内部 `go server.Serve(ln)` 后立即返回，`Run/Listen` 没有阻塞点；同时 `Stop()` 无法唤醒等待者。
- **修复**：
  - 新增 `stopCh chan struct{}` + `stopOnce`；
  - 新增 `WaitStop()`；
  - `Run()` / `Listen()` 在 `startAdapters()` 成功后调用 `WaitStop()` 阻塞；
  - `Stop()` 在关闭 adapter 后 `close(stopCh)` 唤醒。
- **兼容性**：`cmd/http-demo` 里 `app.Run()` 之后残留的 `select {}` 变成不可达代码，不影响编译，可后续清理。
- **验证**：`application/v3` 单测全绿；HTTP/GraphQL/WS 示例可以持续监听（HTTP 已验证）。

### F4 — 跨协议 binding 被错误协议的 resolver 抢占（GraphQL 登录不可用）

- **文件**：`kernel/v3/runtime/binding.go`（新增 `findForProtocol` + 协议感知缓存）、`kernel/v3/runtime/binding_test.go`（新建）
- **现象**：同进程挂载 HTTP + GraphQL 时，GraphQL 的 `login` 报
  `binding not supported for protocol: protocol=graphql binding=AutoStruct type=struct { Username ... }`。
- **根因**：`Find(paramType)` 只按类型选 resolver（后注册优先），不区分协议；`Resolve` 在拿到错误协议的 resolver 后直接返回 `ErrBindingNotSupported`，**不会继续尝试下一个匹配项**。
- **修复**：
  - 新增 `bindingCacheKey{typ, protocol}` 与 `protocolCache`；
  - `findForProtocol` 从后往前遍历，"类型命中 **且** 协议允许"才选中；
  - 若只有"类型命中但协议不允许"的 resolver，保留其信息用于 `ErrBindingNotSupported` 诊断；
  - `Find` 保留原语义（诊断/基准使用）。
- **回归测试**（`binding_test.go`）：
  - `TestBindingRegistryResolveByProtocol`（双协议各自命中 + 缓存隔离）
  - `TestBindingRegistryResolveKeepsRegistrationPriorityWithinProtocol`（协议内仍后注册优先）
  - `TestBindingRegistryResolveReportsProtocolMismatch`
  - `TestBindingRegistryResolveReturnsNotFoundWhenNoTypeMatch`
- **E2E 证据**：`login` 不再报 binding 错误（改为返回 token 字段，见 P5 的 schema 缺口）。

### F5 — WebSocket 迁移到 Socket.IO v4（Engine.IO v4）

- **文件**：
  - `protocol/ws/v3/ws.go`
  - `protocol/ws/v3/socket_conn.go`（新建）
  - `protocol/ws/v3/go.mod`（`googollee/go-socket.io` → `zishang520/socket.io v1.3.2`）
- **根因（两者叠加）**：
  1. `googollee v1.7.0` 只支持 Engine.IO v3，现代 `socket.io-client` v4 完全无法连接；
  2. 该库要求**根命名空间 `/` 必须存在连接处理器**，否则 engine.io 连接在握手后立即关闭，后续 polling POST 读到 `EOF`。
- **修复**：
  - 底层切换到 `github.com/zishang520/socket.io`（维护中的 fork，支持 Socket.IO/Engine.IO v4）；
  - 新增 `socketConn` 适配层，把 `*socket.Socket` 映射为 binding/ws 依赖的最小接口（ID / URL / RemoteAddr / Request / Emit / Join / Leave / Rooms / LeaveAll / Close）；
  - 事件分发改为「连接建立时挂 `OnAny` + 按 routeKey 动态判断」，不再为每个事件单独注册；
  - adapter 自身实现 `BroadcastToRoom` / `BroadcastToNamespace` / `RoomLen`，通过 `MetadataKeyServer` 暴露给 binding。
- **验证**：`cmd/ws-demo`（共享监听）与 `cmd/ws-app-demo`（独立监听）均用 **socket.io-client v4** 跑通
  `auth_register` / `auth_login` / `users_*` / `room_join` / `room_broadcast`。
