# lania-g v3 标准接入模板

## 1. 目标

本文档给出当前多 module 版本下推荐的业务初始化模板。示例中的 module path 统一使用真实 module path `github.com/sao-lang/lania-g/...`。

## 2. 推荐模板

```go
package main

import (
	"log"
	"os"

	application "github.com/sao-lang/lania-g/application/v3"
	loggerintegration "github.com/sao-lang/lania-g/integrations/logger/v3"
	"github.com/sao-lang/lania-g/kernel/v3/module"
	httpprotocol "github.com/sao-lang/lania-g/protocol/http/v3"
)

type UserController struct{}

func (c *UserController) Ping() map[string]string {
	return map[string]string{"ok": "true"}
}

func (c *UserController) Register(r *httpprotocol.Routes) {
	r.Prefix("/users").Get("/ping", c.Ping)
}

func main() {
	root := module.New(module.Metadata{
		Imports: []module.Module{
			httpprotocol.Module(httpprotocol.Config{Addr: ":8080"}),
			loggerintegration.Module(loggerintegration.Config{}),
		},
		Controllers: []any{&UserController{}},
	})

	app, err := application.New(root, application.Options{Logger: os.Stdout})
	if err != nil {
		log.Fatal(err)
	}
	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

## 3. 模板要点

- 只有两个模块构造入口：`module.New(Metadata)` 与 `module.AsGlobal(Metadata)`。
- 协议与集成都以模块形式进入 `Imports`：`http.Module(cfg)`、`logger.Module(cfg)`。
- 路由/订阅声明写在控制器内（`Register` / `Subscribe`），不写在 main。
- 启动只有 `application.New` + `app.Run()`；编译与诊断在其内部完成。
- 监听地址属于协议配置（`http.Config{Addr}`），不再有 `app.Listen`。

## 4. 接入边界

业务接入建议优先依赖以下包族：

- `github.com/sao-lang/lania-g/application/v3`
- `github.com/sao-lang/lania-g/kernel/v3/module`
- `github.com/sao-lang/lania-g/kernel/v3/di`
- `github.com/sao-lang/lania-g/protocol/<proto>/v3`
- `github.com/sao-lang/lania-g/protocol/<proto>/v3/binding`
- `github.com/sao-lang/lania-g/integrations/<name>/v3`

不建议把 `github.com/sao-lang/lania-g/kernel/v3/compiler`、`github.com/sao-lang/lania-g/kernel/v3/runtime`、`github.com/sao-lang/lania-g/kernel/v3/registry` 当作常规业务依赖。

## 5. 排错优先级

推荐按以下顺序排查：

1. `application.New` 返回的错误（模块树/DI/依赖图）。
2. `app.Diagnostics()` 中的协议与路由统计是否与预期一致。
3. 控制器是否放进了某个模块的 `Controllers` 槽位。
4. 协议模块是否加入了根模块的 `Imports`。
5. 启动报告（`Options{Logger}`）中的 `moduleOwners` 是否包含目标模块。
